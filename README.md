## Часть 1. C# (управляемая память, сборщик мусора)

## Тема проекта
**Симулятор умного дома**

Предметная область описывает виртуальный умный дом, в котором есть комнаты,
устройства и сценарии автоматизации. Пользователь может включать и выключать
устройства, ломать и чинить их, а также запускать сценарии, которые управляют
устройствами целой комнаты.

Эта часть — перенос проекта из ЛР 2 на язык с управляемой памятью (C#).
Те же три класса, та же логика, та же проверка правил, но память освобождает
не программист, а сборщик мусора.

## Классы и их ответственность

### 1. `Device` (Устройство)
**Ответственность:** описывает умное устройство внутри комнаты (лампа, телевизор, розетка).

**Поля (все private):**
- `_name` — название устройства;
- `_isOn` — включено ли устройство;
- `_isBroken` — сломано ли устройство;
- `_powerConsumption` — потребляемая мощность (Вт).

**Доступ к данным — через свойства (properties):**
- `Name` — только чтение (сеттер приватный);
- `IsOn`, `IsBroken`, `PowerConsumption` — только чтение снаружи.

**Содержательные методы:**
- `TurnOn()` — включить устройство;
- `TurnOff()` — выключить устройство;
- `Break()` — сломать устройство;
- `Repair()` — починить устройство;
- `ToString()` — текстовое представление.

**Проверяемое правило предметной области:**
> Нельзя включить сломанное устройство.
> Проверка реализована в методе `TurnOn()`: если `_isBroken == true`,
> выводится сообщение об ошибке, и состояние не меняется.

---

### 2. `Scenario` (Сценарий)
**Ответственность:** описывает сценарий автоматизации умного дома (например, «Утренний свет»).

**Поля (все private):**
- `_name` — название сценария;
- `_condition` — условие срабатывания (например, «07:00»);
- `_isActive` — активирован ли сценарий.

**Свойства:** `Name`, `Condition`, `IsActive` — только чтение.

**Содержательные методы:**
- `Activate()` — активировать сценарий;
- `Deactivate()` — деактивировать сценарий;
- `ChangeCondition(...)` — изменить условие срабатывания;
- `ToString()` — текстовое представление.

**Проверяемое правило предметной области:**
> Нельзя запустить неактивный сценарий.
> Проверка реализована в методе `Room.RunScenario()`: если сценарий не активирован,
> выводится сообщение об ошибке, и устройства не включаются.

---

### 3. `Room` (Комната)
**Ответственность:** объединяет устройства и использует сценарий для управления ими.

**Поля (все private):**
- `_name` — название комнаты;
- `_devices` — список устройств (List<Device>) — композиция;
- `_scenario` — ссылка на внешний сценарий — агрегация.

**Содержательные методы:**
- `AddDevice(...)` — добавить устройство в комнату;
- `TurnOnAllDevices()` — включить все устройства;
- `TurnOffAllDevices()` — выключить все устройства;
- `SetScenario(...)` — привязать сценарий к комнате;
- `RunScenario()` — запустить сценарий.

## Связи между классами

### Композиция: `Room` → `Device`
**Что:** комната состоит из устройств.

**Почему композиция:** устройства не могут существовать без комнаты.
Комната сама создаёт их в своём конструкторе, и наружу они не отдаются.
Если уничтожить комнату, устройства станут мусором вместе с ней.

**В C#:** оба поля — ссылки, но различие определяется тем, **кто создаёт объект**.
При композиции целое создаёт часть само.

### Агрегация: `Room` → `Scenario`
**Что:** комната использует сценарий, но не владеет им.

**Почему агрегация:** сценарий создаётся снаружи (в `Main`) и передаётся
готовым через `SetScenario`. Если уничтожить комнату, сценарий продолжает
существовать, потому что на него есть ссылка в `Main`.
